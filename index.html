Section 1 • 3 min

The Problem with Keyword-Only Job Scraping

Most job scrapers run basic regex or substring matching. They treat the letter "R" inside the word "for" as a data science skill, count every mention equally, and miss whether a skill was a strict requirement or a secondary responsibility.

Evaluation Factor Naive Scrapers StackCheck Intelligence
Extraction Accuracy Flat keyword counts with false positives Word-boundary detection with canonical skill aliases
Requirement Weight Counts every bullet point identically Separates requirements from responsibilities with positional multipliers
Duplicate Handling Duplicates skew percentages Deterministic fingerprinting across titles, companies, and locations
Direct Employer Links Generic search redirects Preserves direct application URLs in data tables and cards
Core Questions Answered by StackCheck
  • Which technologies are mandatory requirements versus secondary preferences?
  • How does demand shift across geographic markets (e.g. Pakistan, India, USA, UK, Germany, Remote)?
  • Which skills frequently appear together in the same job postings (co-occurrence synergies like Python + SQL or Snowflake + dbt)?
  • What are the minimum, average, and maximum compensation ranges across specific tech stacks?

Local Data Isolation

All scraped data and project workspaces are stored in a local SQLite file (~/.stackcheck/stackcheck.db). No cloud accounts or telemetry required.

OOP Matplotlib Engine

Charts use explicit fig, ax object-oriented interfaces, avoiding thread-safety issues common to global pyplot states in multi-threaded dashboards.

Technical Component Mapping

Components inside src/stackcheck/:

  • client/hiringcafe.py: Direct payload requests with pagination, workplace filters, and exponential backoff retry.
  • client/normalizer.py: Title classification, geographic country aliases, and duplicate fingerprinting.
  • analyzer/parser.py: Section splitter separating requirements from general description text.
  • analyzer/metrics.py: Skill co-occurrence correlation matrix, salary percentiles, and weighted scoring.
  • storage/repository.py: Multi-workspace SQLite repository handling schema migration and upserts.
  • web/app.py: 3-tab Streamlit interface with multi-select filtering and CSV/JSON/Markdown exports.
Section 3 • 4 min

Ingestion, Deduplication & Quality Filters

Real-world job boards contain spam postings, duplicate reposts across regional offices, and messy location inputs. StackCheck applies a 4-stage cleaning pipeline before storing data.

1. Deterministic Fingerprint

Generates a SHA-256 hash from normalized job title, company name, and location. Reposted ads are updated rather than duplicated.

2. Geographic Normalizer

Maps colloquial entries (e.g. "Lahore", "Bangalore", "Indai", "USA", "NZ") into canonical country names so regional market comparisons remain clean.

3. Workplace & Level Mapping

Classifies postings into Remote, Hybrid, or Onsite, and maps seniority into Entry, Mid, Senior, and Lead categories.

4. Direct Apply Links

Extracts and stores direct employer application links, enabling users to jump straight from the data table to the job posting.

Section 4 • 4 min

Section-Aware Extraction & Priority Weighting

Skills mentioned in the "What We Look For" section matter significantly more than technologies casually listed under "Company Overview" or "Nice-to-Have".

Job Section Base Multiplier Positional Decay Example Insight
Requirements / Qualifications 1.5x 1.8x at top bullet down to 1.0x at bottom Core language (e.g. Python) listed as item #1 gets peak priority score
Responsibilities / Day-to-Day 1.0x 1.2x at top bullet down to 1.0x at bottom Tools used during workflow (e.g. Jira, Slack) get standard priority
Nice-to-Have / Preferred 0.7x Fixed flat multiplier Secondary tools do not distort primary core language counts
Co-occurrence Matrix Calculation

For any pair of technologies (A and B), the co-occurrence frequency measures how often both appear together within the same job advertisement: 

Co-Occurrence Score = Count(Job containing A and B) / Total Analyzed Postings

This reveals practical tech stack combinations, such as the strong affinity between PostgreSQL + FastAPI, or dbt + Snowflake + SQL.

Section 5 • 3 min

Streamlit Dashboard & Interactive Job Explorer

The user interface organizes research data into three focused tabs:

Tab 1: Market Overview

Top demanded skills bar chart comparing frequency percent against weighted requirement scores, accompanied by workplace mode distributions.

Tab 2: Tech Synergies & Salaries

Seaborn correlation heatmap showing co-occurring technologies, paired with min/avg/max compensation benchmark plots.

Tab 3: Interactive Job Explorer

Filterable table supporting multi-select filters for Experience Level, Country, and Skills (ANY or ALL match mode) with direct employer apply links and CSV/JSON export.

Section 6 • 2 min

Portable Packaging & Quick Reference Card

StackCheck is packaged as a portable, self-contained application (like Ventoy or Rufus). It runs without requiring system modifications, external Python installations, or administrator access.

Command Action
stackcheck Launch local browser dashboard at http://localhost:8501
stackcheck scrape "Data Engineer" --location Pakistan Scrape live job postings and store in active SQLite workspace
stackcheck export --format markdown Export an executive summary brief to local markdown
stackcheck update Check GitHub Releases API and update binary in place
